# 智能问询笔录平台（项目实战 2.11）

> 面向公安执法与反诈接处警场景的**结构化问询 + AI 研判 + 五流证据闭环 + 合规文书导出**办案工作台。
> 本项目为《项目实战.md》第 2 部分 **2.11 智能问询笔录平台** 的完整实现，并配套《项目实战-难度排序与推荐方案.md》中对该项目的落地分析。
> **全部案件、人员、手机号、银行卡号、网址、APP 名称均为虚构脱敏数据，仅用于教学演示。**

> **仓库说明**：本仓库为演示精简版，仅保留运行 Demo 所需的代码、模板、示例材料与截图；
> 课程文档、教程、设计分析、运行期数据库与导出文件未纳入版本库。首次启动会自动建库并生成演示数据。

# 1) 安装唯一依赖
pip install python-docx

# 2) 启动服务（首次启动会自动建库并生成演示数据）

# 可选参数
python backend/app.py --port 9000     # 指定端口（默认 8765）
python backend/app.py --demo          # 开放 /demo/session 截图演示入口
python backend/app.py --seed          # 重建演示数据后启动

## 四、技术选型与取舍

| 层 | 选型 | 理由 |
| --- | --- | --- |
| 后端框架 | **Python 标准库 `http.server`** | 环境零风险：课程机房/答辩电脑通常无网、无法 `pip install fastapi`；自研 350 行 HTTP 层即可满足 REST + multipart + Cookie 会话 |
| 数据库 | **SQLite（WAL）** | 单文件随项目携带，免安装、免起服务，`seed.py` 一键重建 |
| 文书 | **python-docx** | 唯一必需第三方依赖，直接产出 Word 可编辑的 DOCX；红头、字号、行距、页码均可精确控制 |
| 前端 | **原生 ES + CSS 变量设计系统** | 无构建、无 CDN、无 node_modules；`file://` 直开也能跑，答辩现场不会因 `npm install` 失败 |
| AI 研判 | **DeepSeek 真实调用（SSE 流式）+ 规则引擎兜底** | 「AI 深度研判」按钮以 SSE 流式请求 `deepseek-chat`，中栏实时渲染模型增量与可读思维链；输出受 JSON 约束并经服务端校验；无密钥/断网时自动回退可解释规则引擎 |
| 会话 | Cookie + 服务端 Session 表 | 与"Cookie 会话管理"需求一致，HttpOnly 防脚本读取 |

> 取舍原则：**把不稳定的外部依赖降为可选增强**，保证"打开就能演示"；但 AI 能力不是装饰——配置密钥后即为真实大模型调用。

### 配置大模型（可选，2 分钟）

系统默认已接入 DeepSeek。密钥**不写入数据库、不进项目目录、不回显前端**，三种配置方式任选：

```bash
# 方式一：环境变量
set PRACTICE_LLM_API_KEY=sk-xxxxxxxx          # Windows
export PRACTICE_LLM_API_KEY=sk-xxxxxxxx       # Linux/macOS

# 方式二：写入用户目录（设置页填写密钥时也是写这里）
python scripts/install_llm_key.py --key sk-xxxxxxxx

# 方式三：启动服务后进入「系统配置 → AI 模型参数」填写并保存
```

配置完成后在「系统配置 → AI 模型参数」点「连通性测试（真实调用）」，或在三栏工作台点「DeepSeek 流式研判」。
未配置密钥时，系统按设计自动回退规则引擎，页面会明确标注「规则引擎（离线可用）」，不会影响演示。

## 五、关键设计速览

| 设计 | 说明 |
| --- | --- |
| **19 类模板 + 通用模板** | 每类 5 章节（固定开头/接触引流/被骗经过/资金损失/证据补充），问题带 `flow`/`field` 元数据，可直接驱动要素抽取 |
| **可解释推荐** | `0.6×信号词命中（饱和 8 个）+ 0.25×特征词语义相似 + 0.15×手法关键词`，界面可展开查看三项分值与命中词 |
| **多模板合并大纲** | 按章节归并、问题文本去重、保留 `source_template`，前端标注"问题来源" |
| **五流引擎三层抽取** | ① 问题元数据定向（模板问题自带 flow/field）② 字段启发式正则 ③ 全文兜底扫描；输出置信度与原文证据片段 |
| **重点缺口判定** | 必填缺失→需补充；**关键要素**缺失→重点缺口；「不涉及」必须人工标记，引擎不自动判定 |
| **追问优先级** | 资金流 > 通信流 > 网络流 > 人员流 > 寄递流，中栏按严重度置顶 |
| **AI 建议合规边界** | 所有建议均为"待采纳"，必须民警点击「加入问询」才写入正式问答，来源标记 `ai_suggested`；大模型输出经字段白名单、问句格式、缺口一致性三重校验 |
| **大模型深度研判（流式）** | 一键真实调用 DeepSeek，**SSE 流式**推送 300+ 增量块与 13 条可读思维链（摘要/类型/置信度/指引/追问），首包约 1.1s、整段 3.1~4.0s / 约 1150 tokens；输出经字段白名单、问句格式、缺口一致性三重校验后落库，失败自动回退并标注原因 |
| **四阶段断点** | `intake → templates → inquiry → completed`，快照含表单、模板、大纲、计时、滚动锚点；「继续询问」按阶段路由并回填 |
| **材料物理隔离** | `material` 表与 `qa_item` 表**无外键、无字段关联**，仅按 `record_id` 归属；导出文书不读取材料 |
| **审计哈希链** | 每条审计记录 `hash = SHA256(prev_hash + payload)`，页面可一键校验完整性 |
| **DOCX 红头** | A4 + 公文页边距、红色机关名、仿宋三号、固定行距 30 磅、"问："加粗、空答过滤、签名落款、页脚页码 |

## 八、已知限制与降级说明

| 限制 | 现状 | 生产化建议 |
| --- | --- | --- |
| 外部系统 | 智研判/智案管为 **Mock 只读接口**（6 条预置案件） | 对接真实接口时替换 `modules/records_api.py` 中 `mock_external_cases` 与 `sync_external` 的数据源 |
| 大模型 | 默认接入 DeepSeek（真实调用）；无密钥时回退规则引擎 | 密钥保存在用户目录或环境变量，不随项目分发；生产环境建议走内网模型网关并做调用审计 |
| 文书 | 支持文本型 DOCX 生成；不支持扫描件解析 | 若需 OCR，可接入 PaddleOCR 后复用 `importer_svc` 的问答切分逻辑 |
| 并发 | 单机 SQLite + 多线程，适合演示与小组办案 | 生产环境迁移 PostgreSQL，接口层已按"仓储即 SQL"隔离 |
| 认证 | 密码 PBKDF2 + HttpOnly Cookie | 生产环境建议接入统一身份认证（OAuth2/OIDC）与 USB-Key |
| 合规 | 演示数据全虚构 | 生产环境需落实等保三级、数据分级分类与办案区物理隔离要求 |

### 安全加固（2026-11-17，依据《安全与性能审查报告》）

- 审计哈希链写入加进程内互斥锁，并发写不再分叉；校验改为增量模式，审计页翻页不全表重算；
- 登录失败 5 次锁定 15 分钟；新账号/重置密码强制 8 位以上且拒绝弱口令；
- LLM `base_url` 白名单：DeepSeek 仅允许官方域名，本机/内网地址默认拒绝，自定义端点须显式声明；
- 导入任务按创建人隔离，历史笔录不可越权转存；
- 修复演示入口开放重定向、静态目录穿越、MIME 伪造、案件编号注入等边界问题；
- 会话 `token` 不再出现在响应体，只走 HttpOnly Cookie；支持 `PRACTICE_COOKIE_SECURE=1`；
- 数据库连接按线程复用，台账/统计批量查询，组织与模板缓存，连接数上限与请求读超时。

生产化前请阅读该报告第五节「残余风险」（多进程审计锁、DNS 重绑定、分布式限流、演示口令、HTTPS 等）。

2. 演示数据中的人名、身份证号、手机号、银行卡号、网址、APP 名称均为构造值（部分卡号校验位不合法即为刻意设计，用于演示"格式待核验"提示）；
3. 材料图片由程序绘制并叠加"虚构演示数据"水印；
4. 系统对 AI 建议设置强制人工采纳环节，材料与正文物理隔离，符合执法程序中"证据法定、笔录真实"的基本要求；
5. 导出的 DOCX 文末均带演示水印说明，正式使用前须去除。
